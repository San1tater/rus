# 廢土求生 (rus)

> Browser-based survival sandbox game built with pure front-end technologies. Current project state indicates a large single-page game with modular JavaScript architecture, UI-driven tab navigation, and multi-system gameplay loops.

## 一、專案定位

這是一款以 HTML + CSS + JavaScript 為核心的純前端生存遊戲，內容聚焦於廢土探索、資源管理、裝備強化、戰鬥、基地建設與農園運營。遊戲邏輯大多由前端狀態管理與畫面渲染組成，資料以 `localStorage` 保存，整個專案可以直接在瀏覽器中載入執行。

目前倉庫的根目錄已經從「歷史版本頁面」進化為「模組化單頁遊戲主體」，核心入口是 `index.html`，將大量功能拆分到 `js/` 目錄中的不同模組，並配套 `styles.css` 及多種資源目錄。

---

## 二、最新程式碼架構概覽

專案採用「單頁應用式分層架構」：

- 入口頁面：`index.html`
- UI 容器：`#app`、`#content`、`#zone1`、`#zone2`、`#zone3`
- 主導覽：`nav#tabbar`
- 主頁面切換：探索 / 戰鬥 / 後院 / 基地
- 畫面與狀態分離：HTML 負責結構，CSS 負責視覺，JS 負責遊戲邏輯與資料流

整體運作可以概括為：

- `index.html` 依序載入多個腳本
- `06-core.js` 充當啟動入口與全域執行循環
- `01-part.js` ~ `05-part.js` 提供主要資料定義與功能邏輯
- `07-garden.js` / `08-base.js` 處理後院與基地系統
- `10-vehicle.js` 處理載具相關功能
- `09-enemy-data.js` 集中定義敵人資料
- `styles.css` 控制整體介面與版面

這種實作方式讓每個模組在功能上相對獨立，同時透過共享的全域 `state` 物件進行協作。

## 四、核心模組設計

### 1. `index.html`
專案入口，承擔三件事：

- 建立遊戲主容器與 UI 區塊
- 注入 tab bar（探索 / 戰鬥 / 後院 / 基地）
- 依序載入各個模組腳本，確保全域功能初始化順序

這代表整個遊戲實際上是「一個頁面多功能區塊切換」架構，而非傳統的多頁遊戲。

### 2. `styles.css`
全域樣式核心，控制：

- 遊戲整體佈局
- 卡片式面板
- 選單與模態框
- 角色/敵人/地圖畫面風格
- 狀態顯示與交互反饋

`styles.cleanup.bak.css` 可視為歷史備份，保留舊版樣式為比對或回滾使用。

### 3. `js/01-part.js`
這是資料層核心，通常負責：

- 物品定義
- 武器 / 護甲 / 彈藥定義
- 裝備稀有度
- 區域、任務、版本設定
- 通用資料表

這是一個典型的「內容資料中心」模組，其他模組大多依賴其中定義的 ID、屬性與數值。

### 4. `js/02-part.js`
偏向視覺與探索介面邏輯，主要承擔：

- 探索畫面渲染
- 戰利品展示
- 玩家互動事件
- 區域內容顯示與 UI 組裝

### 5. `js/03-part.js`
負責狀態保存與流程控制，通常包含：

- `localStorage` 儲存與讀取
- 背包管理
- 道具使用
- 任務或進度流轉
- 玩家狀態更新

它是整體遊戲狀態的關鍵枢紐。

### 6. `js/04-part.js` / `js/05-part.js`
這兩個模組是戰鬥系統的核心：

- Boss 場景邏輯
- 血量與護盾計算
- 傷害模組
- 特殊行為與 AI 判定
- 戰鬥過程 UI

`BossModule` 在 `06-core.js` 中被引用，可見戰鬥系統是全域事件與場景狀態的支柱之一。

### 7. `js/06-core.js`
這是整個專案最關鍵的控制層之一，承擔：

- tab 切換邏輯
- 場景 fade / 轉場動畫
- 遊戲主循環（tick）
- 離線結算
- 初始化流程
- 全域事件與生命週期管理

從程式碼可看出，這裡有明確的「主迴圈 + 狀態檢查 + 畫面更新」模式，屬於典型的前端遊戲框架式設計。

### 8. `js/07-garden.js`
後院系統是本專案的一大亮點，內容相當龐大，包含：

- 土壤與作物系統
- 園藝種植與成長邏輯
- 收成、清理、修復
- 商人/交易池
- 伺服器 / 後勤 / 角色分派
- raid / 戰鬥事件
- 貨物管線與進度模組

這個檔案幾乎等於「基地經營與農業生產系統的總控中心」。

### 9. `js/08-base.js`
基地系統主要處理：

- 設施建造/升級
- 資源加工
- 防禦/保護設施
- 產出節點與資源鏈
- 建築/設施互動邏輯

可視為遊戲的經濟與外圍發展層。

### 10. `js/09-enemy-data.js`
敵人資料中心，負責定義：

- 敵人屬性
- 類型與難度
- 掉落與素材
- 戰鬥相容性

這讓敵人資料不再散落各處，而是集中管理。

### 11. `js/10-vehicle.js`
載具模組，可見專案已經延伸到：

- 車輛 / 運輸系統
- 交通工具設定
- 車場場景或相關互動
- 交通/移動型體驗

### 12. `js/11-render-unify.js` / `js/12-bmp-line.js`
這些屬於更低層的視覺渲染與資源處理/補丁模組，代表專案在持續重構與擴充中，逐步把功能拆出來，提升維護性。

## 五、設計思路與架構邏輯

### 1. 單頁遊戲式架構
遊戲並非由多個 HTML 頁面切換，而是由一個入口頁面與多個功能區塊組成，支援：

- 探索畫面
- 戰鬥畫面
- 後院畫面
- 基地畫面

這種設計極適合即時管理狀態，並減少頁面重載造成的體驗不連續。

### 2. 狀態驅動的渲染模式
大量邏輯都依賴共享 `state` 物件，而不是每次重繪都重新建立整套資料。這讓程式有以下優點：

- 互動更快
- 狀態更易保存
- 容易做離線計算與恢復
- 功能模組可以更方便地共用資料

### 3. 模組化但仍偏大型單檔
雖然已經拆成多個檔案，但整體仍然偏向「大型單頁遊戲」的風格，尤其：

- `07-garden.js` 內容極大
- `10-vehicle.js` 也有很大體量
- `01-part.js` / `02-part.js` / `03-part.js` 也維持長程邏輯

這反映出該專案更像是「反覆擴充與重構過程中的遊戲原型」，而不是純粹的工程化新專案。

### 4. 前端本地化保存
遊戲使用 `localStorage` 保存進度，表示它更偏向「單機、離線、持續進度」體驗，而不是多玩家同步裝置。

### 5. 以功能面板為中心的互動設計
從 `#zone1` / `#zone2` / `#zone3` 和 `#modal-layer` 可以看出，UI 設計不僅是簡單的頁面，而是以「面板 + 彈窗 + 狀態卡」的方式承載互動，符合養成策略遊戲的表現方式。

- 以純前端實作為主體
- 採用單頁遊戲多區塊切換設計
- 具備探索、戰鬥、基地與後院四大系統
- 以 `state` 為核心的狀態管理方式
- 通過 `localStorage` 保存進度
- 功能模組清楚分層：資料層 / UI 層 / 核心控制層 / 系統層
- 具備大量歷史版本與工具頁資料，體現目前仍處於快速迭代狀態

這個專案的本質不是「簡單的靜態頁面」，而是一個已經發展成中大型前端遊戲原型的單機生存遊戲。其最大的特色在於：

- 模組分工已經相當明確
- 核心邏輯相對集中
- 任務與戰鬥系統複雜度高
- 內容豐富，建築、戰鬥、農園和載具系統整合度強

整體架構屬於典型的「前端遊戲工程化雛形」：大而全、功能繁多、資料集中、UI 複雜、模組化逐步增強。
